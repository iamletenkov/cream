# OpenWrt в экосистеме cream: машины на OpenWrt в Teleport и Stvor

> **Отложено владельцем 2026-10-20: заводить OpenWrt в Teleport и Stvor сложно (5–7 недель, риск Teleport на musl);
> спека сохранена как задел, решения В1–В7 и Р1–Р5 записаны.** Плана реализации нет.
>
> 2026-10-20. Решения владельца по §11 (В1–В6 — по рекомендациям, В7 — открытый вопрос владельца) и рулинги
> контроллера по skeptic (Р1–Р5, §12) внесены. Скоуп — от ядра cream до портала Stvor: что нужно, чтобы
> машину на OpenWrt (x86-64, generic arm64, Raspberry Pi 4/5, виртуалки) заводить в Teleport и Stvor одной командой
> из портала, как Debian/Ubuntu-робота. Вход: спека [cream-core](2026-10-18-cream-core.md), код cream `0e522c2`,
> каталог `cream-extensions` `cba0b8b`, bisquite (`examples/build/amd64/openwrt`, `OpenWrtBuilder`),
> `iamletenkov/openwrt-builder` v0.1.0, скрипт установки Stvor (`backend/app/modules/teleport/install_script.py`),
> форк Teleport 18.10 и тарболы на зеркале Stvor.

## 0. Вводные владельца (не пересматриваются)
- Целевое железо: Raspberry Pi 4/5, другие arm64, amd64, виртуальные машины. **Роутеры и слабое железо (MIPS,
  32-битный ARM, < 1 ГБ ОЗУ, флеш в десятки МБ) не поддерживаем** — поэтому статический Go-бинарь cream по размеру
  допустим.
- Машина на OpenWrt заводится в Teleport и Stvor **одной командой из портала**, как робот на Debian/Ubuntu.
- Платформы приёмки: x86-64 и arm64 в ВМ, Raspberry Pi 4/5, мощный arm64-сервер; роутеров нет. Только **OpenWrt
  25.12+** (`apk`), 24.10/`opkg` не поддерживаем (В1). Минимум машины — 1 ГБ ОЗУ и 1 ГБ свободно на корне (В6).
- Приёмка — сборкой образов и ВМ на PVE-ноде `root@192.168.202.206` (VMID 990001–990010, ВМ после себя удалять).

## 1. Цели и не-цели
**Цели**
1. cream ставит, настраивает и снимает расширения на OpenWrt (procd вместо systemd, состояние вне tmpfs).
2. Узел Teleport на OpenWrt: регистрация `token`/`bound_keypair`, метки, приложения — как у робота на Debian.
3. stvor-agent на OpenWrt держит метки узла равными порталу.
4. Портал выдаёт команду установки для OpenWrt; зеркало стенда раздаёт всё нужное офлайн.
5. Регистрация **переживает перезагрузку**.

**Не-цели**
- Роутеры, MIPS, armv7, машины с ОЗУ < 1 ГБ или < 1 ГБ свободного места на корне (ext4-образ).
- OpenWrt 24.10 и старше, `opkg`, пакеты `.ipk`/`.apk` для cream и stvor-agent (В1, В5).
- Управление пакетами OpenWrt (`apk`) из cream — остаётся делом хуков, как apt на Debian.
- Обновление прошивки (`sysupgrade`) средствами cream или Stvor; канал обновлений ОС вне рамок (решение
  владельца 2026-10-18: «ОС не обновляем»). Что переживает ручной `sysupgrade` — §4.7 (В4, Р4).
- Настройка сети/firewall OpenWrt: узел Teleport ходит к прокси исходящим обратным туннелем, входящие порты не нужны.
- BPF-запись сессий, PAM, создание пользователей хоста (`create_host_user`) на OpenWrt.
- Графические стадии (`graphical`) и рабочие столы.

## 2. Факты
### 2.1 OpenWrt
| Факт | Значение и следствие |
|---|---|
| Версии | на 2026-10-20 текущая стабильная — **25.12.6** (2026-10-18), прежняя — 24.10.8 (2026-07-24, «outdated», только ограниченные исправления) — [downloads.openwrt.org](https://downloads.openwrt.org/) |
| Пакетный менеджер | 24.10 — `opkg` (`.ipk`); 25.12 — `apk` (apk-tools 3, формат ADB). Поддерживаем только 25.12+ (В1); пакеты для cream/stvor-agent не делаем (В5) — tar-поставка (§4.3) |
| libc | musl; загрузчика glibc и `gcompat` в фидах нет (в `openwrt/packages` нет ни `gcompat`, ни `teleport`; Go-прецедент — `net/tailscale`) |
| init | procd: `/etc/init.d/<имя>` с `USE_PROCD=1`, `START=NN`, ссылки `/etc/rc.d/S<NN><имя>`; `respawn`; журнал — `logd` (`logread`), `journalctl` нет |
| `/var` | ссылка на `/tmp` (tmpfs): **всё под `/var` пропадает при перезагрузке** |
| `sysupgrade` | переписывает корень; сохраняет `/etc/config`, файлы из `/etc/sysupgrade.conf` и `/lib/upgrade/keep.d/*` (архивом в ОЗУ — сотни МБ туда класть нельзя) |
| `os-release` | `ID=openwrt`, `ID_LIKE="lede openwrt"`, `VERSION_ID=25.12.x` (у снапшотов — `SNAPSHOT`, не поддерживается) |
| Таргеты под вводные | `x86/64` (amd64, ВМ и железо), `armsr/armv8` (generic arm64, EFI: ВМ и серверы), `bcm27xx/bcm2711` (RPi 4), `bcm27xx/bcm2712` (RPi 5) |
| По умолчанию в образе | `busybox` (`ash`, `sha256sum`, `tar`), `uclient-fetch` как `wget`; **нет** `bash`, `curl`, иногда `ca-bundle` |
| `uclient-fetch` и POST | поддерживает `--post-data=STRING` («use the POST method»): метод выбирается флагом `opt_post`, не длиной строки, поэтому `--post-data=''` шлёт POST с пустым телом (исходник `openwrt/uclient`, `uclient-fetch.c`, 2026-10-20). Проверка строки на чистой ВМ 25.12 — приёмка среза 3 |

### 2.4 Teleport (главный риск)
- Тарболы 18.10.0 на зеркале Stvor (`teleport/dist/v18.10.0/linux-{amd64,arm64}/`): `teleport`, `tsh`, `fdpass-teleport`
  — **динамические под glibc** (интерпретатор `/lib64/ld-linux-x86-64.so.2` / `/lib/ld-linux-aarch64.so.1`;
  `libc.so.6`, `libpthread`, `libdl`, `libm`, `libresolv`, `libgcc_s`; символы до `GLIBC_2.17`). `tbot` и
  `teleport-update` — статические (`CGO_ENABLED=0` в Makefile форка). `teleport` — 386 МБ.
- `teleport` без cgo не собирается: безусловный `import "C"` в `lib/system/signal.go`, `lib/cgroup/cgroup.go`,
  `lib/inventory/metadata/metadata_linux.go` (форк `92705fbafc`); BPF — только с тегом `bpf`.
- amd64 у роботов — тарбол форка, arm64 — официальная сборка CE (решение владельца 2026-09-29).
- Teleport перезапускает сам себя через `/proc/self/exe` (дочерние процессы SSH-сессий) — запуск через
  `ld.so --library-path … teleport` это ломает: `/proc/self/exe` укажет на загрузчик.

## 3. Варианты Teleport и рекомендация
| Вариант | Суть | Оценка |
|---|---|---|
| **A. glibc-рантайм рядом** (**выбран**, В3) | `teleport-glibc-runtime_<arch>.tar.gz`: `ld-linux`, `libc.so.6` и ещё 5 библиотек из Debian 12 (glibc 2.36, `nss_files` встроен) в `/opt/teleport/glibc/`; `patchelf --set-interpreter /opt/teleport/glibc/ld-linux-… --set-rpath /opt/teleport/glibc` на `teleport` (и `tsh`, `fdpass-teleport`) **при сборке набора на стенде**, sha256 — пин набора | бинарь кластера тот же (версия, поведение, лицензия как сейчас); `/proc/self/exe` остаётся `teleport`; ≈ 4 МБ сверху. Риски: patchelf на 386-МБ Go-бинаре (проверить сразу, срез 2 начинается с этого); `utmp`/`wtmp` и `getpwnam` через glibc на системе musl — проверить вход по SSH и `os_logins`; двойная libc в системе — только для этого процесса |
| B. Сборка форка под musl (запасной, В3) | cgo с musl-тулчейном (Alpine buildbox или `zig cc`), статическая линковка, `amd64`+`arm64` | чище в рантайме, но новый конвейер сборки форка на 2 архитектуры, arm64 сейчас официальный (форк под arm64 не собирается), sqlite/cgo и тесты под musl — Teleport musl официально не поддерживает. Запасной путь, если A упрётся в patchelf/NSS |
| C. Teleport в контейнере | `dockerd` из фидов OpenWrt, образ Debian с `teleport`, `--net=host --pid=host` | SSH-сессия попадает в файловую систему контейнера, нужен `nsenter`; Docker на RPi — сотни МБ и свой firewall; отвергнут (§10) |
| D. `gcompat` | слой совместимости musl | в фидах OpenWrt нет; на aarch64 ненадёжен; отвергнут |

**Решение (В3):** A как основной путь с проверкой в первый же день среза 2 (ВМ x86-64: `teleport version`, join,
`tsh ssh root@…`, перезагрузка). Не прошло — B, с переоценкой срока (+1–2 недели на конвейер форка). Набор A
собирает стенд Stvor (`scripts/fetch-teleport-tarball.sh` расширяется веткой `openwrt`), а не машина: patchelf на
OpenWrt не нужен. Набор `openwrt-<arch>` — **без `tsh`** (на роботе не нужен, экономит место; Р2): `teleport`,
`fdpass-teleport`, `glibc/`, `SHA256SUMS`.

## 4. Архитектура по слоям
### 4.1 cream core (минорная версия, `cream: ">=1.2.0"`)
1. **Семейство платформы `openwrt`**: `platform.family: openwrt` (определяется по `ID=openwrt` или `ID_LIKE` с
   `openwrt`/`lede`); `platform.os: [{id: openwrt, version: ">=25.12"}]`. Расширение с `family: deb` на OpenWrt — 68,
   как сейчас. Добавление значения — минорное расширение контракта (ADR-0001: совместимость внутри мажора);
   нужен ADR-0003 «семейство openwrt и init procd».
2. **Init как интерфейс**: `internal/systemd` → `internal/initsys` с реализациями `systemd` и `procd`; выбор — по
   семейству хоста (deb → systemd, openwrt → procd), не флагом. Операции: `Running`, `Reload` (procd — no-op),
   `Restart(svc, noBlock)` (`/etc/init.d/<svc> restart`; `--no-block` — запуск фоном), `Stop`, `Enable`.
3. **configure на procd**: один init-скрипт `/etc/init.d/cream-configure` (`USE_PROCD=1`, без `respawn`), который
   проходит включённые расширения по стадиям; стадии — отдельные ссылки `rc.d`:
   | Стадия | procd | Примечание |
   |---|---|---|
   | `early` | `S19cream-configure-early` (до `network` `S20`) | таймаут ≤ 2 мин, как сейчас |
   | `system` | `S95cream-configure` | после сети и `wrt.cloudinit` (`S47`) |
   | `cloud-user` | то же `S95`, после `system` | аналога `cloud-final` нет; `wrt.cloudinit` к `S95` уже отработал |
   | `graphical` | **отказ валидации** на семействе `openwrt` | |
   `after`/`before`/`wants` манифеста (имена юнитов systemd) на `openwrt` запрещены (65) — порядок только стадией.
4. **Раскладка вне tmpfs**: на `openwrt` `var/lib/cream` → `/opt/cream/var` (реестр `installed/`, `ext/<имя>`,
   `sources.lock`, кеш источников). `/etc/cream` (конфиг и секреты) — как есть. Слой `paths.Layout` получает
   семейство; пути Debian не меняются.
5. **`cream system init`** на `openwrt` пишет `/etc/init.d/cream-configure` и включает его (`rc.d`-ссылки).
   Реестр cream **не** попадает в `keep.d` (Р4, §4.7): после `sysupgrade` новый cream стартует с пустым реестром.
6. **Временные каталоги на диске** (Р2): на `openwrt` рабочие каталоги cream (распаковка источников, `ext/<имя>`)
   — под `/opt/cream/var`, а не в `/tmp` (tmpfs = ОЗУ при 1 ГБ на машину); хукам семейства `openwrt` cream выставляет
   `TMPDIR` на каталог под `/opt` (`/opt/cream/var/tmp`).
7. Фаза build (`policy-rc.d`) на `openwrt` не нужна: procd в госте `virt-customize` не запущен, а init-скрипты
   стартуют только через `rc.d`; хук `install` под build не делает `restart`, как уже требует контракт.
8. Валидатор каталога: проверка `systemctl` без `--no-block` дополняется `/etc/init.d/* restart` в хуках `apply`.

### 4.2 Расширения: `cream-extensions/extensions/openwrt/*`
- Корень `extensions/openwrt` с cream/v1-расширениями **`teleport`** и **`stvor-agent`** (те же имена — на них
  завязаны stvor-agent `cream run teleport set-managed` и скрипт Stvor). Дубль имён в одном каталоге запрещён,
  поэтому **отдельный снимок каталога** `cream-extensions-openwrt-<v>.tar.gz` (`roots: [extensions/openwrt]`),
  его собирает тот же `tools/catalog-snapshot.sh`; Stvor раздаёт снимок по семейству.
- **Общее ядро `teleport` (Р3, вариант «б»)**: init-независимая часть `teleport.sh` (рендер `teleport.yaml`, join,
  метки, `apps.d`, `bound_keypair`) — файл `lib/teleport-core.sh` **в одном месте** репозитория `cream-extensions`
  (вне `roots`, сам по себе не расширение). `tools/catalog-snapshot.sh` при сборке снимка кладёт его в
  `files/teleport-core.sh` обоих расширений (`debian/teleport` и `openwrt/teleport`); в git копий нет (проверяет
  `tools/check.sh`). Тесты ядра — одни (`lib/tests/`), гоняются из CI один раз; тесты слоёв — в своих расширениях.
  Контракт cream/v1 **не меняется** (ни новых полей, ни отдельной `kind: library`): для cream это обычный файл в `files`.
  Работа из сырого checkout path-источником идёт только через снимок (`catalog-snapshot.sh`), как уже для релиза.
- **Тонкие слои** (`teleport.sh` каждого семейства подключает `teleport-core.sh` и задаёт):
  | Точка | debian | openwrt |
  |---|---|---|
  | init | юниты `teleport.service`, `teleport-join.{service,timer}`, `teleport-{token,apps}.{path,service}` | `/etc/init.d/teleport` (procd, `respawn`); повтор join — procd-экземпляр с `respawn`; вместо `.path` — прямой вызов из действий `set-managed`/`apps` |
  | перезапуск | `systemctl restart --no-block` | `/etc/init.d/teleport restart` фоном |
  | журнал join | `journalctl -u teleport` с `_SYSTEMD_INVOCATION_ID` | `logread -e teleport` с отсечкой по метке времени старта |
  | архитектура (`install`) | `dpkg --print-architecture` | `uname -m` → `amd64`/`arm64` |
  | каталог данных и «узел зарегистрирован» | `/var/lib/teleport`, `host_uuid` в нём | `/opt/teleport/data`, `host_uuid` в нём |
  | временные файлы | `/tmp` | `TMPDIR=/opt/teleport/tmp` (Р2) |
  | тарбол | `linux-<arch>` с `tsh` | `openwrt-<arch>` без `tsh`, с `glibc/` |
  Копия 1700 строк в два места отвергнута (§10).
- `openwrt/teleport`: `platform.commands: [bash, curl, tar, sha256sum]`; ставит тарбол + glibc-рантайм (§3 A),
  `files: /etc/init.d/teleport` (procd, `respawn`), `data_dir: /opt/teleport/data` вместо `/var/lib/teleport`,
  `/lib/upgrade/keep.d/teleport` (только `/opt/teleport/data` и маркер владения cream — §4.7); `TELEPORT_OS_LOGINS` — только `root`
  (на OpenWrt пользователей с shell обычно нет); BPF/PAM выключены явно в `teleport.yaml`.
- `openwrt/stvor-agent`: тарбол вместо `.deb` (`dpkg` нет), `/etc/init.d/stvor-agent` (procd, `respawn`),
  состояние `/opt/stvor-agent/state` вместо `StateDirectory=`.
- Firewall (`fw4`), `cloud-user`, ресайз — **не** нужны для регистрации; `uci-defaults`/`wrt_cloudinit` остаются
  делом образа (bisquite), перевод их в cream/v1 — вне этой спеки.
- Хуки остаются на bash: пакет `bash` — требование `platform.commands`; скрипт Stvor ставит его сам (§4.5).

### 4.3 Поставка cream и stvor-agent
- **tar.gz, не пакеты** (В5): `cream_<v>_linux_{amd64,arm64}.tar.gz` уже в релизе; установка — распаковка в
  `/usr/bin` + `cream system init`. nfpm apk v3 (ADB) не пишет; пакетов `.ipk`/`.apk` нет, пока их не попросят.
- stvor-agent: новый ассет `stvor-agent_<v>_linux_{amd64,arm64}.tar.gz` + `SHA256SUMS`; бинарь уже статический Go.
  В коде агента — интерфейс `Systemctl` (`Enable`, `Restart`) получает реализацию procd по семейству хоста; без
  systemd-песочницы юнита (`ProtectSystem`, `NoNewPrivileges`…) — на OpenWrt защиты процесса нет, это фиксируется
  в SECURITY.md агента.

### 4.4 Teleport-набор на стенде Stvor
`scripts/fetch-teleport-tarball.sh` получает ветку `openwrt`: из того же тарбола `linux-<arch>` и glibc-рантайма
(Debian 12, пин sha256) собирает `teleport-v<ver>-openwrt-<arch>.tar.gz` (patchelf внутри контейнера сборки), кладёт
на зеркало рядом с `linux-<arch>` и пишет пин в env экземпляра. `make lint-repo` (`check-teleport-pin.sh`) сверяет
новый пин.

### 4.5 Stvor: скрипт установки и портал
- **Один универсальный скрипт** (В2): тот же `#!/bin/sh` (POSIX, годится для `ash`) сам определяет ОС; ОС при
  создании робота не объявляется, как и архитектура (решение 2026-10-13). Ветка `openwrt`:
  ОС — `ID=openwrt`, `VERSION_ID >= 25.12`; архитектура — `uname -m` (`dpkg` нет); проверка «Teleport не от cream» —
  `/etc/init.d/teleport` или `/opt/teleport/data/host_uuid` при пустом `cream list` допустимы **только с маркером
  владения cream** (§4.7), иначе отказ; зависимости — `apk add bash curl ca-bundle`, офлайн — их наличие требуется
  заранее; ОЗУ ≥ 1 ГБ и свободно ≥ 1 ГБ на `/opt` (корень) и достаточно на `/tmp` для самого скрипта — проверка **до**
  любых изменений (В6, Р2); рабочий каталог скрипта — на диске (`mktemp -d /opt/stvor-install.XXXXXX`), не в `/tmp`;
  cream — tar.gz вместо `dpkg -i`; источник — снимок `cream-extensions-openwrt`; далее те же
  `cream install … teleport`, `cream run teleport join`, `cream install stvor-agent`.
- **Нет набора для архитектуры** (Р5): если в пинах экземпляра нет `openwrt`-набора (cream tar.gz, снимок, Teleport
  `openwrt-<arch>`, stvor-agent tar.gz) для архитектуры машины, скрипт отказывает понятным сообщением («OpenWrt
  `<arch>` на этом экземпляре не поддержан: нет …») до изменений на хосте. Одноразовый код к этому моменту погашен —
  **осознанно**: владелец выпускает новый после выкладки набора.
- **Команда на портале и POST** (Р1): в OpenWrt по умолчанию нет `curl` и `sudo`, есть `wget` (`uclient-fetch`,
  https через `libustream`), вход — `root`. Сервер принимает **`POST`** к install-эндпоинту
  (`backend/app/modules/teleport/robot_api.py`, `robot_install`) как равноценный `GET` с `X-Stvor-Install: 1`:
  предпросмотр ссылок мессенджерами и сканеры `POST` не шлют, `HEAD`/`GET` без заголовка по-прежнему код не
  расходуют. Портал показывает две строки (`install_code.render_command` + новое `render_command_openwrt`, поле
  `InstallCodeOut.command_openwrt`):
  - Debian/Ubuntu — без изменений: `sudo -v && curl -fsSL -H "X-Stvor-Install: 1" https://…/install/<код> | sudo bash`;
  - OpenWrt — `wget -qO- --post-data='' 'https://…/install/<код>' | sh` (без `sudo`).
- Набор бутстрапа (`downloads.py`, `robot_arches`) получает измерение семейства: набор `openwrt` доступен, когда есть тарбол cream, снимок
  `cream-extensions-openwrt`, Teleport-набор `openwrt-<arch>` и (робот) stvor-agent tar.gz.
- «Загрузки»: строки для OpenWrt не нужны (люди ставят `tsh` на свои машины, не на OpenWrt).

### 4.6 bisquite и openwrt-builder
- `openwrt-builder`: поддержка **25.12** — параллельный PR в `iamletenkov/openwrt-builder` (вне этого плана); от него
  здесь нужны qcow2 `x86/64` (срезы 1–3) и затем `armsr/armv8`, `bcm27xx/bcm2711`, `bcm27xx/bcm2712` (срез 4); в образ
  — `bash`, `curl`, `ca-bundle`, `ROOTFS_SIZE` ≥ 2048 (Teleport-набор без `tsh` ~ 400 МБ распакованным + место на
  обновление; минимум машины — 1 ГБ свободно, В6).
- bisquite: пример `examples/build/amd64/openwrt` переводится на базу **25.12** из релиза `openwrt-builder` (В1);
  `RUN_COMMAND opkg …` в документации и примерах → `apk`.
- bisquite: `EXTENSION` для OpenWrt разрешается, когда в каталоге есть cream/v1-расширения семейства `openwrt`
  (сборка — `virt-customize`, как сейчас `RUN_COMMAND`); до этого — без изменений. Отдельной задачей срезов 1–3 не
  является: регистрация идёт командой с портала на живой машине.

### 4.7 `sysupgrade` (В4, Р4)
- `/lib/upgrade/keep.d/teleport` (кладёт `openwrt/teleport` через `files`) перечисляет **только** `/opt/teleport/data`
  (ключи, `host_uuid`, состояние `bound_keypair`) и **маркер владения cream** `/opt/teleport/.cream-owned` (пишет
  хук `install` расширения; содержимое — имя расширения и версия cream). Реестр cream (`/opt/cream/var`), `/etc/cream`,
  бинари и `/etc/init.d/*` **не** сохраняются: новый cream стартует с пустым реестром.
- После `sysupgrade` узел офлайн (бинарей нет). Восстановление: владелец жмёт **«Новый секрет»** на портале и
  повторяет команду. Скрипт видит `host_uuid` без записи в `cream list`, находит маркер — признаёт регистрацию «от
  cream», ставит cream и расширения заново, `join` с новым секретом сохраняет прежний `host_uuid` (тот же узел в
  Teleport, без дубля). Без маркера — отказ «Teleport не от cream», как на Debian.
- Сценарий «регистрация → `sysupgrade` (тот же образ) → «Новый секрет» → команда → тот же узел онлайн» — тест в
  приёмке среза 3 и финальной.

## 5. Поток регистрации (целевой)
```
портал → «Добавить робота» → строка OpenWrt:
  wget -qO- --post-data='' …/install/<код> | sh
  sh: проверки (ID=openwrt ≥ 25.12, arch и набор в пинах, root, ОЗУ/место, нет Teleport не от cream)
     → apk add bash curl ca-bundle → cream tar.gz → cream system init (init.d) → cream source add stvor (снимок openwrt)
     → cream install teleport (тарбол openwrt-<arch> с зеркала) → cream run teleport join (секрет на stdin)
     → cream install stvor-agent (tar.gz) → /etc/init.d/stvor-agent enable+start
перезагрузка → S95cream-configure → teleport (procd respawn) с данными в /opt/teleport/data
```

## 8. Риски
1. **Teleport на musl через patchelf** (вероятность провала ~30 %): Go-бинарь на 386 МБ, NSS/utmp glibc на чужой
   системе. Смягчение — проверка в первый день среза 2, запасной вариант B.
2. **tmpfs `/var` и `sysupgrade`**: любой путь под `/var/lib` в расширении теряет регистрацию на reboot. Смягчение —
   раскладка `/opt/*` в cream и расширениях, проверка валидатором каталога (`/var/lib` в `files`/хуках семейства
   `openwrt` — предупреждение), e2e с перезагрузкой.
3. **Расхождение двух `teleport`** (debian/openwrt): правка join в одном и забытая в другом. Смягчение — общая
   библиотека, один набор тестов ядра, CI каталога гоняет оба снимка.
4. Место на диске: Teleport-набор ~ 450 МБ, на образах с `ROOTFS_SIZE` 512 МБ установка упадёт. Смягчение —
   проверка свободного места в скрипте Stvor до скачивания, минимум в В6.
5. ~~Два пакетных менеджера~~ — снят решением В1 (только 25.12+/`apk`).
6. **Одноразовый код и отказ скрипта** (Р5): отказ после погашения кода требует нового кода. Принято осознанно;
   смягчение — проверки ОС/архитектуры/набора идут первыми, сообщение называет, чего нет.

## 9. Безопасность
- Секрет регистрации — по-прежнему на stdin `cream run teleport join`; на OpenWrt нет systemd-песочницы для
  stvor-agent и teleport — процессы root без ограничений; это явно в SECURITY.md stvor-agent и README расширения.
- glibc-рантайм — по пину sha256 с зеркала стенда, собирается из Debian 12 по пину; обновление glibc при CVE —
  пересборка набора (runbook Stvor 07 дополняется).
- `keep.d` хранит ключи узла Teleport в архиве `sysupgrade` (в ОЗУ на время обновления) — допустимо, как
  `/etc/config`.
- `POST` на install-эндпоинте (Р1): код — секрет в пути; кросс-сайтовая форма может погасить код только зная его, а
  ответ (скрипт) чужому источнику не читается (CORS не открываем). Погашение кода `POST`-ом пишется в аудит так же,
  как `GET` с заголовком.

## 10. Отвергнутые варианты
| Вариант | Почему нет |
|---|---|
| Teleport в Docker-контейнере на OpenWrt | SSH-сессии в ФС контейнера, `nsenter`-обёртки, Docker на RPi тяжёл и вмешивается в fw4 |
| `gcompat` | нет в фидах OpenWrt, на aarch64 ненадёжен |
| Запуск `teleport` через `ld.so --library-path` без patchelf | `/proc/self/exe` указывает на загрузчик — ломает перезапуск самого себя для SSH-сессий |
| glibc в `/lib` по стандартным путям | смешивает `libgcc_s` и другие библиотеки musl/glibc в одном пути поиска; ломает систему при обновлении пакетов |
| Пакеты `.ipk`/`.apk` как основной канал | два формата, apk v3 (ADB) nfpm не пишет; tar.gz уже выпускается (В5) |
| Поддержка 24.10 (`opkg`) | «outdated», второй пакетный менеджер в скрипте и образах (В1) |
| Выбор ОС при создании робота на портале | ОС, как и архитектуру, скрипт определяет сам (В2) |
| `kind: library` `teleport-core` для ядра | `platform.family` у библиотеки одно, а снимки по семействам раздельные — библиотека всё равно легла бы в оба корня копией; плюс лишняя единица в реестре и `depends` ради одного файла (Р3) |
| Ядро `teleport` в `debian/teleport` с симлинком из `openwrt/teleport` | снимок и path-источник по-разному обходятся с симлинками; одно место вне `roots` проще (Р3) |
| Сохранять реестр cream через `keep.d` | реестр ссылается на бинари и файлы, которых после `sysupgrade` нет — рассинхрон хуже пустого реестра (Р4) |
| Заголовок `X-Stvor-Install` в строке OpenWrt | `uclient-fetch` умеет `--header`, но busybox-`wget` на части сборок — нет; `POST` поддерживают оба (Р1) |
| Копия `teleport.sh` в `extensions/openwrt/teleport` | 1700 строк в двух местах — гарантированное расхождение join/меток |
| Одно расширение `teleport` с ветками по семейству в одном каталоге | `files` не умеют условия по семейству, `platform.family` — одно значение; потребовало бы мажорной правки формата |
| Имена `teleport-openwrt`/`stvor-agent-openwrt` | stvor-agent и скрипт Stvor завязаны на имя `teleport`; правка контракта агента ради имени |
| Хранить состояние в `/etc` | `/etc` — конфиг; кеш источников и реестр раздули бы архив `sysupgrade` |
| Поддержать роутеры (MIPS/armv7, мало флеша) | вне вводных владельца; 386-МБ `teleport` туда не влезает |

## 12. Рулинги по skeptic (контроллер, 2026-10-20)
| № | Риск | Решение |
|---|---|---|
| Р1 | Строка `wget … \| sh` не может послать `X-Stvor-Install`, а без него код не гасится (защита от предпросмотра ссылок) | сервер принимает `POST` к install-эндпоинту как равноценный заголовку; строка OpenWrt — `wget -qO- --post-data='' '<url>' \| sh` без `sudo`; строка Debian/Ubuntu — как есть. `--post-data` у `uclient-fetch` подтверждён по исходнику (§2.1); строка на чистой ВМ 25.12 — приёмка среза 3 (§4.5) |
| Р2 | `/tmp` и `/var` — tmpfs (ОЗУ); распаковка ~400 МБ при 1 ГБ ОЗУ кончится OOM | рабочие каталоги расширений и скрипта Stvor на `openwrt` — на диске (`/opt/teleport/tmp`, `TMPDIR`, `/opt/cream/var/tmp`, `mktemp -d /opt/…`); скрипт проверяет место на `/opt` и `/tmp`; набор `openwrt-<arch>` без `tsh` (§3, §4.1, §4.5) |
| Р3 | Как делить 1700 строк `teleport.sh` без изменения контракта | `lib/teleport-core.sh` в `cream-extensions` в одном месте; `tools/catalog-snapshot.sh` кладёт его в оба расширения; тесты ядра одни; контракт cream/v1 не меняется; тонкие слои перечислены (§4.2) |
| Р4 | Реестр cream после `sysupgrade` указывает на пропавшие файлы | `keep.d` сохраняет только идентичность узла и маркер владения cream; реестр не сохраняется (§4.7) |
| Р5 | Нет набора `openwrt` для архитектуры в пинах экземпляра | скрипт отказывает с понятным сообщением; код сгорает — осознанно, владелец выпускает новый (§4.5, §8) |
