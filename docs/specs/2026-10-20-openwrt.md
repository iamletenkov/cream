# OpenWrt в экосистеме cream: машины на OpenWrt в Teleport и Stvor

> 2026-10-20. **Черновик** спеки (исследование, кода нет). Скоуп — от ядра cream до портала Stvor: что нужно, чтобы
> машину на OpenWrt (x86-64, generic arm64, Raspberry Pi 4/5, виртуалки) заводить в Teleport и Stvor одной командой
> из портала, как Debian/Ubuntu-робота. Вход: спека [cream-core](2026-10-18-cream-core.md), код cream `0e522c2`,
> каталог `cream-extensions` `cba0b8b`, bisquite (`examples/build/amd64/openwrt`, `OpenWrtBuilder`),
> `iamletenkov/openwrt-builder` v0.1.0, скрипт установки Stvor (`backend/app/modules/teleport/install_script.py`),
> форк Teleport 18.10 и тарболы на зеркале Stvor. Перед планом — skeptic и ответы владельца на §11.

## 0. Вводные владельца (не пересматриваются)
- Целевое железо: Raspberry Pi 4/5, другие arm64, amd64, виртуальные машины. **Роутеры и слабое железо (MIPS,
  32-битный ARM, < 1 ГБ ОЗУ, флеш в десятки МБ) не поддерживаем** — поэтому статический Go-бинарь cream по размеру
  допустим.
- Машина на OpenWrt заводится в Teleport и Stvor **одной командой из портала**, как робот на Debian/Ubuntu.

## 1. Цели и не-цели
**Цели**
1. cream ставит, настраивает и снимает расширения на OpenWrt (procd вместо systemd, состояние вне tmpfs).
2. Узел Teleport на OpenWrt: регистрация `token`/`bound_keypair`, метки, приложения — как у робота на Debian.
3. stvor-agent на OpenWrt держит метки узла равными порталу.
4. Портал выдаёт команду установки для OpenWrt; зеркало стенда раздаёт всё нужное офлайн.
5. Регистрация **переживает перезагрузку**.

**Не-цели**
- Роутеры, MIPS, armv7, устройства без ext4/overlay-раздела ≥ 2 ГБ.
- Управление пакетами OpenWrt (`opkg`/`apk`) из cream — остаётся делом хуков, как apt на Debian.
- Обновление прошивки (`sysupgrade`) средствами cream или Stvor; канал обновлений ОС вне рамок (решение
  владельца 2026-10-18: «ОС не обновляем»). Что переживает ручной `sysupgrade` — §11, В4.
- Настройка сети/firewall OpenWrt: узел Teleport ходит к прокси исходящим обратным туннелем, входящие порты не нужны.
- BPF-запись сессий, PAM, создание пользователей хоста (`create_host_user`) на OpenWrt.
- Графические стадии (`graphical`) и рабочие столы.

## 2. Факты
### 2.1 OpenWrt
| Факт | Значение и следствие |
|---|---|
| Версии | на 2026-10-20 текущая стабильная — **25.12.6** (2026-10-18), прежняя — 24.10.8 (2026-07-24, «outdated», только ограниченные исправления) — [downloads.openwrt.org](https://downloads.openwrt.org/) |
| Пакетный менеджер | 24.10 — `opkg` (`.ipk`); 25.12 — `apk` (apk-tools 3, формат ADB). Два формата пакетов — довод за tar-поставку (§4.3) |
| libc | musl; загрузчика glibc и `gcompat` в фидах нет (в `openwrt/packages` нет ни `gcompat`, ни `teleport`; Go-прецедент — `net/tailscale`) |
| init | procd: `/etc/init.d/<имя>` с `USE_PROCD=1`, `START=NN`, ссылки `/etc/rc.d/S<NN><имя>`; `respawn`; журнал — `logd` (`logread`), `journalctl` нет |
| `/var` | ссылка на `/tmp` (tmpfs): **всё под `/var` пропадает при перезагрузке** |
| `sysupgrade` | переписывает корень; сохраняет `/etc/config`, файлы из `/etc/sysupgrade.conf` и `/lib/upgrade/keep.d/*` (архивом в ОЗУ — сотни МБ туда класть нельзя) |
| `os-release` | `ID=openwrt`, `ID_LIKE="lede openwrt"`, `VERSION_ID=24.10.1`/`25.12.x` |
| Таргеты под вводные | `x86/64` (amd64, ВМ и железо), `armsr/armv8` (generic arm64, EFI: ВМ и серверы), `bcm27xx/bcm2711` (RPi 4), `bcm27xx/bcm2712` (RPi 5) |
| По умолчанию в образе | `busybox` (`ash`, `sha256sum`, `tar`), `uclient-fetch` как `wget`; **нет** `bash`, `curl`, иногда `ca-bundle` |

### 2.2 Что есть сейчас
- **bisquite**: `OpenWrtBuilder` (`src/bisquite/infrastructure/build/builders/openwrt.py`) собирает образ из готового qcow2
  через `virt-customize`/`virt-sysprep` (+ своя дочистка идентичности), только под архитектуру хоста; запрещает
  `RESIZE`, `EXTENSION` («расширения рассчитаны на apt и systemd»), `INSTALL/UNINSTALL/UPGRADE` (замена —
  `RUN_COMMAND opkg …`), `FIRSTBOOT*` (замена — `firstboot-commands` через `wrt.cloudinit`). Деплой в Proxmox
  (`deploy/proxmox/adapter.py`) распознаёт OpenWrt (`is_openwrt`) и кладёт firstboot-команды своим способом.
- **`examples/build/amd64/openwrt/openwrt.vmfile`**: база `openwrt-24.10.1-custom-x86-64-generic-ext4-combined-efi.qcow2`
  из релиза `openwrt-builder` v0.1.0; слои — `/var/lock`, авторесайз (`uci-defaults` `70-rootpt-resize`,
  `80-rootfs-resize`, оба в `sysupgrade.conf`, две перезагрузки), `wrt.cloudinit` (procd, `START=47`) с библиотекой.
  `examples/deploy/openwrt.yml` — ВМ 2 ядра / 2 ГБ / диск 2G.
- **`iamletenkov/openwrt-builder`** v0.1.0 (2026-06-25): ImageBuilder в Docker, **только `x86/64` 24.10.1**
  (`TARGET`/`SUBTARGET` параметризованы, но CI собирает один таргет), `ROOTFS_SIZE` 1024; в образе уже есть `bash`,
  `curl`, `ca-certificates`, `coreutils`, `shadow-useradd`, `qemu-ga`, `python3-light` и большой набор LuCI/VPN.
- **cream-extensions**: `extensions/openwrt/` содержит только layout 2 (`uci-defaults`, `wrt_cloudinit`), не cream/v1;
  корень каталога `roots: [extensions/debian]`; дубли имён в каталоге запрещены (`catalog.duplicate_name`).

### 2.3 Привязки cream к Debian/systemd (код `0e522c2`)
| Место | Привязка |
|---|---|
| `internal/systemd` (`init.go`, `stage.go`, `unit.go`, `systemctl.go`) | шаблон `cream-configure@.service`, стадии через `*.wants`, drop-in `10-stage.conf`, `systemctl is-system-running/daemon-reload/restart/stop`. `Systemctl` — уже интерфейс (`engine.go`), это точка расширения |
| `internal/paths/paths.go` | `var/lib/cream` (реестр и состояние) — **на OpenWrt tmpfs**; `usr/lib/systemd/system`, `etc/systemd/system` |
| `internal/engine/policyrcd.go`, `build.go` | `policy-rc.d` для фазы build — только Debian |
| `internal/manifest/validate.go`, `internal/resolve/host.go` | `platform.family: deb` — единственное значение; `os.id` ожидается `debian`/`ubuntu` |
| `internal/lock` | `flock(2)` через syscall — на musl-ядре работает |
| Сборка | `CGO_ENABLED=0`, статический бинарь — от libc не зависит; DNS — чистый Go (`/etc/resolv.conf`), CA — `/etc/ssl/certs/ca-certificates.crt` (пакет `ca-bundle`) |
| Упаковка | `.deb` через nfpm + `cream_<v>_linux_{amd64,arm64}.tar.gz` в релизе (tar уже есть) |
| Хуки | любые исполняемые файлы с shebang; расширения `teleport` и `stvor-agent` — bash (`#!/usr/bin/env bash`, ассоциативные массивы), `teleport.sh` — 1721 строка, 35 вызовов `systemctl`, `journalctl` для диагностики join |

### 2.4 Teleport (главный риск)
- Тарболы 18.10.0 на зеркале Stvor (`teleport/dist/v18.10.0/linux-{amd64,arm64}/`): `teleport`, `tsh`, `fdpass-teleport`
  — **динамические под glibc** (интерпретатор `/lib64/ld-linux-x86-64.so.2` / `/lib/ld-linux-aarch64.so.1`;
  `libc.so.6`, `libpthread`, `libdl`, `libm`, `libresolv`, `libgcc_s`; символы до `GLIBC_2.17`). `tbot` и
  `teleport-update` — статические (`CGO_ENABLED=0` в Makefile форка). `teleport` — 386 МБ.
- `teleport` без cgo не собирается: безусловный `import "C"` в `lib/system/signal.go`, `lib/cgroup/cgroup.go`,
  `lib/inventory/metadata/metadata_linux.go` (форк `92705fbafc`); BPF — только с тегом `bpf`.
- amd64 у роботов — тарбол форка, arm64 — официальная сборка CE (решение владельца 2026-09-29).
- Teleport перезапускает сам себя через `/proc/self/exe` (дочерние процессы SSH-сессий) — запуск через
  `ld.so --library-path … teleport` это ломает: `/proc/self/exe` укажет на загрузчик.

## 3. Варианты Teleport и рекомендация
| Вариант | Суть | Оценка |
|---|---|---|
| **A. glibc-рантайм рядом** (рекомендуется для срезов 1–3) | `teleport-glibc-runtime_<arch>.tar.gz`: `ld-linux`, `libc.so.6` и ещё 5 библиотек из Debian 12 (glibc 2.36, `nss_files` встроен) в `/opt/teleport/glibc/`; `patchelf --set-interpreter /opt/teleport/glibc/ld-linux-… --set-rpath /opt/teleport/glibc` на `teleport` (и `tsh`, `fdpass-teleport`) **при сборке набора на стенде**, sha256 — пин набора | бинарь кластера тот же (версия, поведение, лицензия как сейчас); `/proc/self/exe` остаётся `teleport`; ≈ 4 МБ сверху. Риски: patchelf на 386-МБ Go-бинаре (проверить сразу, срез 2 начинается с этого); `utmp`/`wtmp` и `getpwnam` через glibc на системе musl — проверить вход по SSH и `os_logins`; двойная libc в системе — только для этого процесса |
| B. Сборка форка под musl | cgo с musl-тулчейном (Alpine buildbox или `zig cc`), статическая линковка, `amd64`+`arm64` | чище в рантайме, но новый конвейер сборки форка на 2 архитектуры, arm64 сейчас официальный (форк под arm64 не собирается), sqlite/cgo и тесты под musl — Teleport musl официально не поддерживает. Запасной путь, если A упрётся в patchelf/NSS |
| C. Teleport в контейнере | `dockerd` из фидов OpenWrt, образ Debian с `teleport`, `--net=host --pid=host` | SSH-сессия попадает в файловую систему контейнера, нужен `nsenter`; Docker на RPi — сотни МБ и свой firewall; отвергнут (§10) |
| D. `gcompat` | слой совместимости musl | в фидах OpenWrt нет; на aarch64 ненадёжен; отвергнут |

**Рекомендация:** A как основной путь с проверкой в первый же день среза 2 (ВМ x86-64: `teleport version`, join,
`tsh ssh root@…`, перезагрузка). Не прошло — B, с переоценкой срока (+1–2 недели на конвейер форка). Набор A
собирает стенд Stvor (`scripts/fetch-teleport-tarball.sh` расширяется веткой `openwrt`), а не машина: patchelf на
OpenWrt не нужен.

## 4. Архитектура по слоям
### 4.1 cream core (минорная версия, `cream: ">=1.2.0"`)
1. **Семейство платформы `openwrt`**: `platform.family: openwrt` (определяется по `ID=openwrt` или `ID_LIKE` с
   `openwrt`/`lede`); `platform.os: [{id: openwrt, version: ">=24.10"}]`. Расширение с `family: deb` на OpenWrt — 68,
   как сейчас. Добавление значения — минорное расширение контракта (ADR-0001: совместимость внутри мажора);
   нужен ADR-0003 «семейство openwrt и init procd».
2. **Init как интерфейс**: `internal/systemd` → `internal/initsys` с реализациями `systemd` и `procd`; выбор — по
   семейству хоста (deb → systemd, openwrt → procd), не флагом. Операции: `Running`, `Reload` (procd — no-op),
   `Restart(svc, noBlock)` (`/etc/init.d/<svc> restart`; `--no-block` — запуск фоном), `Stop`, `Enable`.
3. **configure на procd**: один init-скрипт `/etc/init.d/cream-configure` (`USE_PROCD=1`, без `respawn`), который
   проходит включённые расширения по стадиям; стадии — отдельные ссылки `rc.d`:
   | Стадия | procd | Примечание |
   |---|---|---|
   | `early` | `S19cream-configure-early` (до `network` `S20`) | таймаут ≤ 2 мин, как сейчас |
   | `system` | `S95cream-configure` | после сети и `wrt.cloudinit` (`S47`) |
   | `cloud-user` | то же `S95`, после `system` | аналога `cloud-final` нет; `wrt.cloudinit` к `S95` уже отработал |
   | `graphical` | **отказ валидации** на семействе `openwrt` | |
   `after`/`before`/`wants` манифеста (имена юнитов systemd) на `openwrt` запрещены (65) — порядок только стадией.
4. **Раскладка вне tmpfs**: на `openwrt` `var/lib/cream` → `/opt/cream/var` (реестр `installed/`, `ext/<имя>`,
   `sources.lock`, кеш источников). `/etc/cream` (конфиг и секреты) — как есть. Слой `paths.Layout` получает
   семейство; пути Debian не меняются.
5. **`cream system init`** на `openwrt` пишет `/etc/init.d/cream-configure` и `/lib/upgrade/keep.d/cream`
   (`/etc/cream`, `/opt/cream/var` без кеша источников — состояние в килобайтах).
6. Фаза build (`policy-rc.d`) на `openwrt` не нужна: procd в госте `virt-customize` не запущен, а init-скрипты
   стартуют только через `rc.d`; хук `install` под build не делает `restart`, как уже требует контракт.
7. Валидатор каталога: проверка `systemctl` без `--no-block` дополняется `/etc/init.d/* restart` в хуках `apply`.

### 4.2 Расширения: `cream-extensions/extensions/openwrt/*`
- Корень `extensions/openwrt` с cream/v1-расширениями **`teleport`** и **`stvor-agent`** (те же имена — на них
  завязаны stvor-agent `cream run teleport set-managed` и скрипт Stvor). Дубль имён в одном каталоге запрещён,
  поэтому **отдельный снимок каталога** `cream-extensions-openwrt-<v>.tar.gz` (`roots: [extensions/openwrt]`),
  его собирает тот же `tools/catalog-snapshot.sh`; Stvor раздаёт снимок по семейству.
- Общее ядро `teleport.sh` (рендер `teleport.yaml`, join, метки, apps.d) выносится из `debian/teleport` в
  init-независимую библиотеку (`kind: library`, спека cream §4.5); OS-зависимое (юниты/init-скрипты, журнал join —
  `logread -e teleport` вместо `journalctl`, `_SYSTEMD_INVOCATION_ID` → метка времени старта) — тонкие слои в
  `debian/teleport` и `openwrt/teleport`. Копия 1700 строк в два места отвергнута (§10).
- `openwrt/teleport`: `platform.commands: [bash, curl, tar, sha256sum]`; ставит тарбол + glibc-рантайм (§3 A),
  `files: /etc/init.d/teleport` (procd, `respawn`), `data_dir: /opt/teleport/data` вместо `/var/lib/teleport`,
  `keep.d/teleport` (ключи, `host_uuid`, `bound_keypair`-состояние); `TELEPORT_OS_LOGINS` — только `root`
  (на OpenWrt пользователей с shell обычно нет); BPF/PAM выключены явно в `teleport.yaml`.
- `openwrt/stvor-agent`: тарбол вместо `.deb` (`dpkg` нет), `/etc/init.d/stvor-agent` (procd, `respawn`),
  состояние `/opt/stvor-agent/state` вместо `StateDirectory=`.
- Firewall (`fw4`), `cloud-user`, ресайз — **не** нужны для регистрации; `uci-defaults`/`wrt_cloudinit` остаются
  делом образа (bisquite), перевод их в cream/v1 — вне этой спеки.
- Хуки остаются на bash: пакет `bash` — требование `platform.commands`; скрипт Stvor ставит его сам (§4.5).

### 4.3 Поставка cream и stvor-agent
- **tar.gz, не пакеты**: `cream_<v>_linux_{amd64,arm64}.tar.gz` уже в релизе; установка — распаковка в `/usr/bin` +
  `cream system init`. Один путь для 24.10 (`opkg`) и 25.12 (`apk` v3/ADB), без nfpm-форматов: `ipk` nfpm умеет, а
  apk v3 — нет (nfpm пишет apk v2; поддержку v2 в apk-tools 3 на OpenWrt не проверяли). Пакеты — открытый вопрос В5.
- stvor-agent: новый ассет `stvor-agent_<v>_linux_{amd64,arm64}.tar.gz` + `SHA256SUMS`; бинарь уже статический Go.
  В коде агента — интерфейс `Systemctl` (`Enable`, `Restart`) получает реализацию procd по семейству хоста; без
  systemd-песочницы юнита (`ProtectSystem`, `NoNewPrivileges`…) — на OpenWrt защиты процесса нет, это фиксируется
  в SECURITY.md агента.

### 4.4 Teleport-набор на стенде Stvor
`scripts/fetch-teleport-tarball.sh` получает ветку `openwrt`: из того же тарбола `linux-<arch>` и glibc-рантайма
(Debian 12, пин sha256) собирает `teleport-v<ver>-openwrt-<arch>.tar.gz` (patchelf внутри контейнера сборки), кладёт
на зеркало рядом с `linux-<arch>` и пишет пин в env экземпляра. `make lint-repo` (`check-teleport-pin.sh`) сверяет
новый пин.

### 4.5 Stvor: скрипт установки и портал
- Скрипт уже `#!/bin/sh` и POSIX (кроме `curl … | bash` в подсказке) — годится для `ash`. Ветка `openwrt`:
  ОС — `ID=openwrt`, `VERSION_ID >= 24.10`; архитектура — `uname -m` (`dpkg` нет); проверки «Teleport не от cream» —
  по `/etc/init.d/teleport` и `/opt/teleport/data/host_uuid`; зависимости — `opkg install` / `apk add`
  (`bash curl ca-bundle`), офлайн — их наличие требуется заранее; cream — tar.gz вместо `dpkg -i`; источник —
  снимок `cream-extensions-openwrt`; далее те же `cream install … teleport`, `cream run teleport join`,
  `cream install stvor-agent`.
- **Команда на портале**: в OpenWrt по умолчанию нет `curl`, есть `wget` (`uclient-fetch`, https через
  `libustream`). Команда для OpenWrt — `wget -qO- '<url>' | sh`. Как портал выбирает команду — В2.
- `Bootstrap.arches` получает измерение семейства: набор `openwrt` доступен, когда есть тарбол cream, снимок
  `cream-extensions-openwrt`, Teleport-набор `openwrt-<arch>` и (робот) stvor-agent tar.gz.
- «Загрузки»: строки для OpenWrt не нужны (люди ставят `tsh` на свои машины, не на OpenWrt).

### 4.6 bisquite и openwrt-builder
- `openwrt-builder`: матрица CI `{x86/64, armsr/armv8, bcm27xx/bcm2711, bcm27xx/bcm2712}` × релиз **25.12** (и 24.10,
  если В1 оставит её); в образ — `bash`, `curl`, `ca-bundle` (уже есть в x86-сборке), `ROOTFS_SIZE` ≥ 2048
  (Teleport-набор ~ 450 МБ распакованным + место на обновление).
- bisquite: `EXTENSION` для OpenWrt разрешается, когда в каталоге есть cream/v1-расширения семейства `openwrt`
  (сборка — `virt-customize`, как сейчас `RUN_COMMAND`); до этого — без изменений. Отдельной задачей срезов 1–3 не
  является: регистрация идёт командой с портала на живой машине.

## 5. Поток регистрации (целевой)
```
портал → «Добавить робота» (OpenWrt) → wget -qO- …/install.sh | sh
  sh: проверки (ID=openwrt, arch, root, нет Teleport не от cream) → apk/opkg: bash curl ca-bundle
     → cream tar.gz → cream system init (init.d, keep.d) → cream source add stvor (снимок openwrt)
     → cream install teleport (тарбол openwrt-<arch> с зеркала) → cream run teleport join (секрет на stdin)
     → cream install stvor-agent (tar.gz) → /etc/init.d/stvor-agent enable+start
перезагрузка → S95cream-configure → teleport (procd respawn) с данными в /opt/teleport/data
```

## 8. Риски
1. **Teleport на musl через patchelf** (вероятность провала ~30 %): Go-бинарь на 386 МБ, NSS/utmp glibc на чужой
   системе. Смягчение — проверка в первый день среза 2, запасной вариант B.
2. **tmpfs `/var` и `sysupgrade`**: любой путь под `/var/lib` в расширении теряет регистрацию на reboot. Смягчение —
   раскладка `/opt/*` в cream и расширениях, проверка валидатором каталога (`/var/lib` в `files`/хуках семейства
   `openwrt` — предупреждение), e2e с перезагрузкой.
3. **Расхождение двух `teleport`** (debian/openwrt): правка join в одном и забытая в другом. Смягчение — общая
   библиотека, один набор тестов ядра, CI каталога гоняет оба снимка.
4. Место на диске: Teleport-набор ~ 450 МБ, на образах с `ROOTFS_SIZE` 512 МБ установка упадёт. Смягчение —
   проверка свободного места в скрипте Stvor до скачивания, минимум в В6.
5. Два пакетных менеджера (opkg/apk): скрипт Stvor ветвится. Смягчение — поддерживать только 25.12 (В1).

## 9. Безопасность
- Секрет регистрации — по-прежнему на stdin `cream run teleport join`; на OpenWrt нет systemd-песочницы для
  stvor-agent и teleport — процессы root без ограничений; это явно в SECURITY.md stvor-agent и README расширения.
- glibc-рантайм — по пину sha256 с зеркала стенда, собирается из Debian 12 по пину; обновление glibc при CVE —
  пересборка набора (runbook Stvor 07 дополняется).
- `keep.d` хранит ключи узла Teleport в архиве `sysupgrade` (в ОЗУ на время обновления) — допустимо, как
  `/etc/config`.

## 10. Отвергнутые варианты
| Вариант | Почему нет |
|---|---|
| Teleport в Docker-контейнере на OpenWrt | SSH-сессии в ФС контейнера, `nsenter`-обёртки, Docker на RPi тяжёл и вмешивается в fw4 |
| `gcompat` | нет в фидах OpenWrt, на aarch64 ненадёжен |
| Запуск `teleport` через `ld.so --library-path` без patchelf | `/proc/self/exe` указывает на загрузчик — ломает перезапуск самого себя для SSH-сессий |
| glibc в `/lib` по стандартным путям | смешивает `libgcc_s` и другие библиотеки musl/glibc в одном пути поиска; ломает систему при обновлении пакетов |
| Пакеты `.ipk`/`.apk` как основной канал | два формата, apk v3 (ADB) nfpm не пишет; tar.gz уже выпускается |
| Копия `teleport.sh` в `extensions/openwrt/teleport` | 1700 строк в двух местах — гарантированное расхождение join/меток |
| Одно расширение `teleport` с ветками по семейству в одном каталоге | `files` не умеют условия по семейству, `platform.family` — одно значение; потребовало бы мажорной правки формата |
| Имена `teleport-openwrt`/`stvor-agent-openwrt` | stvor-agent и скрипт Stvor завязаны на имя `teleport`; правка контракта агента ради имени |
| Хранить состояние в `/etc` | `/etc` — конфиг; кеш источников и реестр раздули бы архив `sysupgrade` |
| Поддержать роутеры (MIPS/armv7, мало флеша) | вне вводных владельца; 386-МБ `teleport` туда не влезает |
