## Дорожки, волны и владение файлами
Одна дорожка = один репозиторий = один исполнитель за раз (внутри репозитория задачи **последовательны**, файлы
пересекаются через `engine`/`schemas`). Дорожки разных репозиториев идут параллельно; одновременно — **не больше 3
исполнителей** (ВМ гаснет под нагрузкой), тяжёлое (`make ci`, сборка образов, e2e в QEMU, работа на PVE) — по одному
через `make heavy` в Stvor и замок `HEAVY_LOCK` в cream.

### Task 2: `internal/initsys`: systemd и procd
- **Файлы:** `internal/systemd` → `internal/initsys` (`systemd.go`, `procd.go`, `fake.go`, тесты), вызовы в

- **Тесты сначала:** выбор реализации по семейству (deb → systemd, openwrt → procd), не флагом; procd: `Restart`

  `Reload` — no-op, `Running` — по `ubus call service list` или наличию procd (через fake-исполнитель команд).
  Существующие тесты systemd проходят без изменений поведения.
- **Приёмка:** `make test` зелёный целиком (Debian-поведение не изменилось — golden CLI те же).

### Task 4: `system init` и `configure` на procd, валидатор каталога
- **Файлы:** `internal/initsys/procd_init.go` (шаблон `/etc/init.d/cream-configure`), `internal/engine` (`system

- **Тесты сначала:** `cream system init` на `openwrt` пишет `/etc/init.d/cream-configure` (`USE_PROCD=1`, без
  `respawn`) и ссылки `rc.d` `S19cream-configure-early`, `S95cream-configure`; **не** пишет `keep.d` (Р4); повторный

- **Приёмка:** `make lint`, `make test` зелёные; golden CLI для `system init --json` на openwrt.

  — онлайн без нового секрета; (5) `sysupgrade` тем же образом → «Новый секрет» → повтор команды → **тот же
  `host_uuid`**, узел онлайн, дубля в `tctl nodes ls` нет (Р4); (6) ВМ на 512 МБ ОЗУ — понятный отказ (В6);
  (7) предпросмотр ссылки (`GET` без заголовка, `HEAD`) код не гасит.
- **Приёмка:** протокол с выводом команд — в отчёте контроллера; `docs/STATUS.md` cream и Stvor обновлены.
