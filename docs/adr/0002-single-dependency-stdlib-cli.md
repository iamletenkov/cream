# 0002. Одна внешняя зависимость (yaml), CLI на stdlib `flag`, пакет через nfpm без goreleaser

- **Status:** Accepted
- **Date:** 2026-10-18
- **Deciders:** Letenkov Maksim (владелец)
- **Tags:** dependencies, cli, packaging, security

## Контекст и проблема
cream работает от root на каждой машине и внутри образов, разбирает чужие архивы и манифесты. Каждая зависимость —
это аудит, обновления Renovate, находки `govulncheck` и вклад в размер статического бинаря (а пакет несёт три
бинаря: свой и два гостевых). Нужно решить, из чего собран CLI и чем собирается пакет, пока кода мало и поменять
легко.

## Рассмотренные варианты
- **Вариант A — stdlib везде, кроме YAML.** CLI — `flag` с перестановкой аргументов (~200 строк), semver-диапазоны —
  свой код, `flock` — `syscall.Flock`, tar/gzip/http/sha256 — stdlib; YAML — `go.yaml.in/yaml/v3`. Пакет — nfpm в
  контейнере с пином, выпуск — release-please + `gh release upload`.
- **Вариант B — cobra/pflag, библиотека semver, goreleaser.** Готовые автодополнение и справка, меньше своего кода;
  но десятки транзитивных модулей и вторая система выпуска рядом с release-please.
- **Вариант C — go-git для git-источников.** Без внешнего `git`, но десятки транзитивных зависимостей ради источника,
  которого на роботах нет (там — архив).

## Решение
Выбран вариант A. В `go.mod` ровно одна внешняя зависимость — `go.yaml.in/yaml/v3` (поддерживаемый форк
`gopkg.in/yaml.v3`, строгий разбор с `KnownFields`). CLI — stdlib `flag`: по `FlagSet` на команду, глобальные флаги
регистрируются и до имени команды, и среди её аргументов; флаги принимаются после позиционных, `--` прекращает
разбор, у `cream run` перестановка останавливается на `<ext>` (Р13). `.deb` собирает nfpm (образ
`goreleaser/nfpm` с закреплённым тегом) по `packaging/nfpm.yaml`; goreleaser не используется. git-источники в 1.0
зарезервированы, позже — внешний `git` (`Suggests: git`).

## Обоснование
Нужные возможности CLI (подкоманды, флаги где угодно, справка) закрываются небольшим своим кодом, который покрыт
тестами вместе с конвертом `--json`. Автодополнение и стиль справки cobra здесь не нужны. Одна зависимость —
предсказуемый `govulncheck` и воспроизводимая сборка. release-please уже ведёт версии и `CHANGELOG.md`; nfpm + `gh`
— та же схема, что у агента, без второго описания выпуска.

## Последствия
- **Положительные:** маленькая поверхность атаки и аудита; сборка без сети после `go mod download`; `make vuln` и
  `make repro-check` проще.
- **Отрицательные:** перестановку аргументов, справку и semver-диапазоны поддерживаем сами; автодополнения shell нет.
- **Действия:** новая зависимость — только решением спеки (регламент `AGENTS.md`); задача 23 проверяет, что в
  `go.mod` ровно одна внешняя зависимость; флаги команд не повторяют имена глобальных (Р14).
