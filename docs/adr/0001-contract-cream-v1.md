# 0001. Контракт cream/v1: формат расширения, пути на машине, CLI и коды выхода

- **Status:** Accepted
- **Date:** 2026-10-18
- **Deciders:** Letenkov Maksim (владелец)
- **Tags:** format, cli, paths, compatibility

## Контекст и проблема
cream исполняет расширения на живых машинах и в фазе build внутри `virt-customize`. У него три внешних
потребителя: каталог `cream-extensions` (пишет манифесты), bisquite (зовёт `cream resolve` и
`cream install --phase build`, разбирает JSON) и stvor-agent (зовёт `cream run --json` и `cream actions --json`).
Всё, что они видят, после выпуска 1.0 трудно поменять: манифесты лежат в чужом репозитории, реестр — на машинах и в
образах, разбор JSON и кодов — в коде других проектов.

Нужно один раз зафиксировать, что входит в контракт, как он версионируется и какие решения спеки становятся его
частью.

## Рассмотренные варианты
- **Вариант A — один версионированный контракт `cream/v1`.** Формат `extension.yaml` (`schema: cream/v1`),
  `cream-catalog.yaml`, `sources.yaml`, раскладка путей на машине, реестр `cream-state/v1`, команды и флаги CLI, коды
  выхода, конверт `--json` и формы `result` версионируются вместе. Совместимость — внутри мажора.
- **Вариант B — независимые версии у формата, CLI и реестра.** Гибче, но потребителю приходится сверять три версии,
  а у bisquite и stvor-agent — матрица совместимости.
- **Вариант C — оставить layout 2 bisquite параллельно.** Отвергнут спекой (§18): переходной совместимости не нужно,
  два формата — два набора багов.

## Решение
Выбран вариант A. Контракт `cream/v1` — это:
1. **Формат** манифеста `cream/v1` (спека §4), каталога и `sources.yaml` (§9.1); разбор строгий (`KnownFields`).
   Отложенное из §17 распознаётся и отклоняется 65 `manifest.reserved` / `source.reserved` (Р1, Р3, Р4).
2. **Пути на машине** (§5): `/usr/bin/cream`, `/opt/cream/ext/<ext>/`, `/etc/cream/{sources.yaml,<ext>/config,
   <ext>/secrets}`, `/var/lib/cream/{installed,ext,lock,incoming}/`, `/var/lib/cream/{history.jsonl,sources.lock}`,
   `/var/cache/cream/sources/`, шаблон `cream-configure@.service`; гостевые бинари на хосте сборки —
   `/usr/lib/cream/guest/linux-{amd64,arm64}/cream`. Блокировки — в `/var/lib/cream/lock`, а не в `/run`.
   `--root DIR` переносит все пути под корень; режим пользователя — XDG.
3. **CLI** (§11.2) и **коды выхода** (§11.3): 0, 1, 0–63 у `cream run`, 64–70, 74–77, 79 — значения не меняются
   никогда; строковый `error.code` стабилен.
4. **`--json`**: ровно один объект в stdout, конверт `{cream, command, ok, result, warnings, error}` (§11.4),
   формы `result` закреплены golden-файлами `internal/cli/testdata/golden/` и описаны в [docs/cli.md](../cli.md).
5. **Реестр** `cream-state/v1` (§10): реестр новее исполнителя — 74 `state.newer`.

Правило изменения: в минорных версиях cream поля и значения только **добавляются** (новые поля JSON, новые
необязательные ключи манифеста, новые команды); удаление, переименование и смена смысла — только в `cream/v2` вместе
с мажорной версией cream. Манифест объявляет совместимый диапазон `cream:`, его мажор равен мажору схемы.

## Обоснование
Один номер контракта проще для всех трёх потребителей: «cream 1.x понимает всё `cream/v1`». Стабильные коды выхода и
golden-формы позволяют bisquite и stvor-agent ветвиться по коду и полю, а не по тексту. Пути без `/run` одинаково
работают на машине и в appliance `virt-customize`.

## Последствия
- **Положительные:** потребители пишут разбор один раз; изменение формы ловит golden-тест до слияния; отложенное
  резервируется так, что манифесты v1 не придётся менять при его реализации.
- **Отрицательные:** поле JSON, выпущенное в 1.0, остаётся до 2.0, даже если оказалось лишним; ошибки дизайна путей
  исправляются только мажором.
- **Действия:** golden-файлы меняются только добавлением полей (ревью проверяет дифф); [docs/cli.md](../cli.md)
  обновляется вместе с формой.

Следствия, ставшие частью контракта (рулинги плана, на сведение владельцу):
- **Р1** — отложенное в манифесте и `sources.yaml` — 65 `*.reserved`; отложенные флаги и команды — 64
  `usage.reserved`.
- **Р2** — `CREAM_LOCK_FD` передаёт только `lock/<ext>`; вложенной операции, которой нужна `lock/global`, — 75.
- **Р3** — из стадий configure в v1 есть только `system`; `early`, `cloud-user`, `graphical` зарезервированы.
- **Р4** — `secret: hook`, `hooks.secret`, `hooks.check`, `bin`, `targets.build: files` — зарезервированы.
- **Р5** — фаза `cream run` — `CREAM_PHASE` окружения, иначе `live`.
- **Р6** — `record.json` фазы build — один слой `cream resolve --json`; cream в госте сверяет `ext_digest` и
  `params_digest`.
- **Р7** — `umask 022` на процесс, хуки наследуют.
- **Р8** — `cream upgrade` ищет версию в источнике из реестра; источника нет — 69 `source.missing`.
- **Р9** — проверки root и прав файлов — только при `--root /`.
- **Р10** — тип `host`: DNS-имя, IPv4 или IPv6 с необязательным `:port`.
- **Р11** — расширение A может класть файлы в каталог настроек B; владение — по реестру A, конфликт 67 — только при
  том же `dst` у другого расширения.
