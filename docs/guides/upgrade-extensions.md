# Обновить расширения

`cream upgrade` устроен как `apt upgrade` / `dnf upgrade`: сначала **план** по
каждому расширению, потом действия. Все команды этой страницы требуют root.
Новые версии берутся из кеша того источника, откуда расширение поставлено, — сначала
обновите источник ([подключить каталог](add-catalog.md)):

```bash
sudo cream source add core --archive "$NEW_URL" --sha256 "$NEW_SUM" --replace --sync
```

## Посмотреть план

```bash
sudo cream upgrade --all --dry-run
```

```
agent     1.0.0 → 1.1.0  будет обновлено
firewall  1.0.0 → 1.1.0  пропущено (риск): firewall: targets.live: confirm (…) — обновление только с --accept-risk firewall
noop      1.0.0          без изменений
teleport  4.0.0          закреплено — снять: cream unhold teleport
План: будет обновлено 1, без изменений 1, пропущено 2 (риск: firewall; закреплено: teleport), ошибок 0
```

Что бывает в плане:

| Действие | Когда | Что делает cream |
|---|---|---|
| `upgrade` | в источнике версия выше | хук `upgrade` (нет его — `install` с `CREAM_PREV_VERSION`) |
| `retry` | та же версия, запись `failed` или `failed-upgrade` | повторяет сорвавшуюся операцию |
| `up-to-date` | новее ничего нет | ничего: ни хука, ни проверок платформы и риска |
| `held` | расширение закреплено `cream hold` (только `--all`) | пропускает |
| `skipped` | `--all`, расширение поставлено не из источника (`--from-dir`) | пропускает с предупреждением `upgrade.no_source` |
| `blocked` | обновление есть, но его нельзя сделать — причина ниже | пропускает |

Причины `blocked`:

| Причина | Почему | Код |
|---|---|---|
| `risk` | `targets.live: confirm` без `--accept-risk <имя>` | 68 `target.confirm` |
| `platform` | новой версии не подходит машина: архитектура, ОС, команды, версия cream | 68 `platform.*` |
| `dependency` | граф: новой версии нужна другая версия зависимости, конфликт, цикл; или поставщик не обновился в этом запуске | 67 `deps.*`, `conflict.*` |
| `held` | `cream upgrade <имя>` для закреплённого | 68 `hold.held` |
| `source` | источника из реестра нет в `sources.yaml` или расширения нет в его кеше | 69, 66 |
| `version` | в источнике версия ниже или та же версия с другим отпечатком | 65 `version.*` |

`--dry-run` ничего не меняет; его код выхода — как у будущего запуска по плану
(есть `blocked` — ненулевой), поэтому его можно звать в CI перед выкладкой.

## Обновить

```bash
sudo cream upgrade --all                    # все, кроме закреплённых
sudo cream upgrade agent noop               # только эти
sudo cream upgrade --all --accept-risk firewall
sudo cream upgrade --all --accept-risk all  # все targets.live: confirm — осознанно
```

- **Порядок** — по зависимостям: поставщик раньше потребителя.
- **Сбой одного не останавливает остальные.** Пропускаются только зависимые от
  него (`blocked:dependency`, `deps.failed`). Упавшее расширение получает статус
  `failed-upgrade`, прежнее дерево сохраняется, повтор — та же команда.
- **Итог** — строка сводки и код выхода по худшему исходу:

```
Итого: обновлено 3, без изменений 5, пропущено 1 (риск: firewall), ошибок 0
```

| Код | Когда |
|---|---|
| 0 | всё обновлено или уже актуально; закреплённые и `no_source` при `--all` — не ошибка |
| 79, 74, 75… | хотя бы одно обновление упало — код первого упавшего |
| 67, 68, 69, 65 | упавших нет, но что-то `blocked` — код первого пропущенного |
| 1 | в терминале ответили «нет» на план — ничего не изменено (`upgrade.declined`) |

Прежнее поведение «остановиться на первой проблеме» — `--fail-fast`: пропуск в плане
останавливает всё до первого действия, первая ошибка — остальное (`not_run`).

С одним именем (`cream upgrade agent`) результат и ошибка — этого расширения, как
в cream 1.1.

## Подтверждение в терминале

Если stdin и stderr — терминал (а не `cron`, юнит systemd, канал или
`/dev/null`) и нет `-y`, `--dry-run`, `--json`, cream:

1. про каждое `targets.live: confirm` с обновлением спрашивает
   `Обновить на живой машине? [y/N]` (показывает `live_note` расширения);
2. показывает план и спрашивает `Продолжить? [y/N]`. «Нет» — код 1, ничего не изменено.

Пока cream ждёт ответа, он держит `lock/global` (как `apt` — блокировку dpkg):
другие изменяющие команды cream ждут `--lock-timeout` и завершаются кодом 75.
В автоматизации вопросов нет — stdin там не терминал.

`-y` (`--yes`) снимает оба вопроса, но **не** риск: такие расширения без
`--accept-risk` останутся `blocked:risk` — как `apt` не трогает удержанные пакеты
без явного указания.

## Закрепить версию

```bash
sudo cream hold teleport       # upgrade --all пропускает, upgrade teleport отказывает (68 hold.held)
sudo cream list                # закреплённые помечены «закреплено»
sudo cream unhold teleport     # снять
```

Закрепление хранится в записи реестра (`/var/lib/cream/installed/<ext>.json`, поле
`held`) и пишется под `lock/global`, как остальной реестр; `install` той же
версии его сохраняет, `install` другой версии отказывает так же, как `upgrade`.
`remove` снимает его вместе с записью.

## В скриптах

```bash
cream upgrade --all --json > plan.json; rc=$?
jq -r '.result.plan[] | select(.status == "blocked") | "\(.name): \(.reason)"' plan.json
```

Форма ответа — [`--json`](../reference/json-output.md#upgrade), коды —
[коды выхода](../reference/exit-codes.md).
